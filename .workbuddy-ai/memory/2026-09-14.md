## Superseded: home section is now a manual curation list, not "latest 3"

The user asked for the home "Selected work" section to be an explicitly curated selection keyed on
`order` — e.g. ASPIRE (11), OpenDebate (15), My-Agent (16). So the recency-based approach was
replaced.

### Final implementation (`app/data/projects.ts`)
```ts
/** Which projects appear in the home page "Selected work" section. ... */
export const selectedProjectOrders = [11, 15, 16];

/** The projects named in `selectedProjectOrders`, kept in that exact order. */
export const selectedProjects = selectedProjectOrders
  .map((order) => projects.find((project) => project.order === order))
  .filter((project): project is Project => project !== undefined);
```
`projects-section.tsx` imports `selectedProjects` (plus `projects` for the CTA count) and maps it.

Two properties worth remembering:
- **Array order is display order.** The grid slots are positional (`index === 0` → large
  `col-span-8`, `index === 1` → small `col-span-4`, `index === 2` → full-width `col-span-12`), so
  reordering `selectedProjectOrders` also changes which project gets which card size.
- Unknown order numbers are filtered out rather than throwing, so a typo silently drops a card
  instead of breaking the build. Worth remembering when editing the list.

Because the selection is now manual, the "Selected work" heading and the "A compact selection
from..." copy are accurate again — no copy change was needed after all.

### Verified
`tsc --noEmit` and `eslint` clean. Against the dev server on port 3000: renders exactly
aspire → open-debate → my-agent; grid spans resolve to 1× large, 1× small, 2× full-width
(My-Agent + the archive card); CTA reads "16 projects and growing"; archive order still starts at
Ghibli Chat.

Note on reading rendered HTML for this project: class strings appear **twice** in the response
(once in the DOM, once in the serialised RSC flight payload), so `grep -c` returns 2× the real DOM
count. Also, interpolated values like `{projects.length}` sit in their own text node and render as
`>16<!-- --> projects and growing`, so a plain `[0-9]* projects` grep will not match.

### Now-unused
`latestProjects` (added earlier today) is superseded by `selectedProjects`, and `featuredProjects`
plus the `featured` flag on 6 projects are also unused. All left in place in case they are wanted —
the user has reverted twice, so nothing was deleted without being asked.
